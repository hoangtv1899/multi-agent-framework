IDEAS · the first box

Reception Walkthrough

How a sentence from a user becomes reception.json: one language-model loop that decides what is being asked, which model should answer it, where and when — and then ordinary code that fetches, once, everything the rest of the pipeline will ever be allowed to know about that place. Reception is the only component that reaches outside the framework. Everything downstream reads what it wrote.

In plain language

Reception takes one request in natural language and returns one package. The package has two halves that are made in two different ways.

The first half is a brief, and a language model writes it. The model classifies the request (a real place, a controlled sweep, a coupling, or a question it cannot yet answer), decides which simulation model should run it, resolves the watershed and the simulation period, and frames the scientific question. It has five tools and no data: it can look up a watershed, look up an elevation, list the servers that are installed, read what each one says about itself, and — when a person is present — ask them a question. It fetches no observations and knows no model facts. What a model can and cannot do it learns by reading that model's own report, in the conversation, every time.

The second half is everything else, and plain code makes it after the model has finished: the elevation grid clipped to the basin, the daily rain at every point on it, the observations for the resolved period (gauges, wells, snow pillows, flux towers, and a modelled water table), and the subsurface properties of the whole basin. These are not decisions, so they are not the model's. They are fetched once, written beside the brief, and never fetched again by anyone — the planner, the sampler, the experiment manager and the analyzer all read this one file.

The seam between the halves is deliberate. Judgement goes to the model; retrieval goes to code; and the model is told, in its own instructions, that the retrieval will happen after it finishes and is not its concern.

2

Scope and boundaries

The framework is four stages in sequence — Reception, Planner, Experiment Manager, Analyzer. Each writes one boundary artifact. Reception is the first, and it ends the moment LLMReceptionAgent.process() returns. What happens to the package after that — the model check, the plan, the dispatch — belongs to the coordinator in workflow.py, not to reception.

Reception ownsReception does not own
Classifying the request and choosing the design archetype Any fact about a model. Which years it can be forced over, how it starts, what it can be pinned to, what a sweep may vary — all read from the model server's report at request time. The prompt states none of it.
Choosing which model server answers the question, and saying why, and separately saying whether it can run today Whether the framework can drive that model. _adopt_model in the coordinator checks the choice against RUNNABLE; reception names the right instrument regardless, and the run stops at dispatch with the package saved if nothing can drive it.
Resolving the watershed and the simulation period, and refusing a period the chosen model's forcing cannot cover Designing the study. No column counts, no bands, no station pins. A count the user stated is recorded as a constraint; nothing else is decided.
Fetching, once, the grid, the rain, the observations and the subsurface for the resolved place and period Summarising or interpreting what it fetched. The model never sees the observations. Code writes a compact summary for the planner; the raw series go to the analyzer.
Recording every fetch, its arguments and its outcome in provenance, including the ones it chose not to make Naming the run directory. The coordinator mints it before reception runs — reception needs somewhere to write two GeoTIFF/NPZ products — and it is still named for the default model, not the one reception chose.

Is reception.json the single authoritative output?

Yes, and it is written in one place — workflow._save_reception, called twice: on the way into planning, and again when a run stops at dispatch, so an honest "cannot drive this model" does not cost the three minutes of fetching that preceded it. It drops two keys from the in-memory package — trace (the tool conversation) and raw (the unparsed reply) — and writes reception_brief.json beside it as an alias for the standalone tools. Two file products land next to it, written by the servers reception called: wtd_conus2.tif and conus2_subsurface.npz + .json.

Nuance worth knowing. The package carries the raw observation series — 80 to 400 KB for a one-year Naches request, dominated by 299 Fan wells and the daily rain. Nothing summarises them on the way in. That is the point: the analyzer compares against exactly what was fetched, and a second fetch could disagree with the first.

Step-by-step execution

The model's steps are the numbered sections of reception_agentic.txt; they are instructions, not code, and the model may take them in whatever order the request needs. The code steps run in the order written, after the model has emitted its JSON.

Step 1 — Classify the intent LLM

Readsthe request; CONVERSATION CONTEXT when the coordinator passes one (the prior run directory, focus, column count and archetype, and up to ten resumable_runs).
Decidesone of four intents: design, clarification_needed, analyze_existing, resume.
RuleA resume may name only a run_dir that appears verbatim in resumable_runs; a partial or constructed name resumes somebody else's study. Two candidates or none → run_dir: null and a question.
Becomesroute.action — mapped by _route(), kept out of the brief because it is dispatch, not science. Anything unrecognised, including a parse failure, routes to clarify.

Step 2 — Choose the archetype LLM

Decidessite (a real place), conceptual (a controlled sweep — a mechanism, no basin), or coupling (one model's output drives another).
Why it mattersIt picks which half of the planner prompt applies, and it is the gate on the code gather: a conceptual brief fetches nothing. A conceptual brief that resolved a basin anyway has it dropped by code and the drop recorded — the model both classified it as a sweep and found a watershed, and a reader should see that happened.

Step 2a — Choose the model LLM

Callslist_servers, then describe_server on each plausible candidate — at least two whenever two are plausible. Both are local tools: the framework answers them from the MCP configuration and a cache, and no server is contacted until one is named.
Readsthe report whole and verbatim: model (the server's one-line account, read literally), ready (measured, not asserted), pinning.pinnable (strong evidence about what the model computes), pinning.not_pinnable[].basis — "model" is physics, "design decision" says nothing about the physics — and constraints.
RuleFit and runnability are two fields. model names the right instrument. can_run_a_study is the framework's flag, not the server's; a model that fits and cannot be driven is named anyway, and model_availability says so. The run then stops at dispatch with the package saved — the correct outcome, and one somebody can act on.
Nevername a model from memory. A server may have been renamed, may be missing a dependency, or may model something narrower than its name suggests. If nothing usable is listed, model: null and a conflict.
Writesmodel, model_rationale, model_availability.

What is not in the prompt. No list of models, no menu, no summary written before the request was read. There was one until 2026-08-17 — a dozen lines per server rendered at construction — and one of its lines was a verdict ("Do not choose it"). The two tools replaced it, at the cost of two extra rounds on every reception, because a choice reasoned from what the servers actually say is worth more than a fast one. A report is 5–10 KB and the loop caps a tool result at 12,000 characters, which is why describe_server takes one name and a repeat call is answered from cache with already_asked: true.

Step 2b — Settle the sweep LLM · conceptual only

Callsdescribe_sweep on the model chosen in 2a; then ask_user. Nothing about what a model can vary is written in the prompt: the menu is the server's JSON, and the prompt only says how to read it — factors[].name is the only string that may be written into the brief; suggested_levels present means offer a default, absent means the value must be asked; held_fixed_options go in held_fixed, never in factors; always_true is said before the user agrees.
RuleNever emit a design the user has not seen. Never say "as you asked" for a choice you made. Never describe what is not in the JSON. Record how each item was settled — user, suggested or default — because the caveats on the result depend on it.
If the server offers no sweepsay so, do not invent factors, record it in run_settings.conflicts. That is a true statement about that server, not a failure.
Writessweep {factors, held_fixed, held_fixed_settled_by, n_columns, forcing_site_rationale, unresolved}. The model and its rationale stay at the top level.

Step 3 — Resolve the domain LLM · site only

Callsterrain.resolve_watershed; terrain.get_elevation as a fallback for a bare point or town.
RuleAmbiguity is asked, never self-resolved: several HUC matches, an unclear HUC scale (a name that is both a HUC6 basin and HUC8 sub-basins), or a vague place → ask_user with the concrete candidates. In batch mode, the most defensible reading, recorded in conflicts. Only numbers a tool returned are stated; coordinates, areas and counts are never invented.
Writesdomain {name, huc, bbox, area_km2, elevation_range_m, source}.

Step 4 — Frame the problem LLM

Writesscientific_framing {goals, key_processes, candidate_drivers}, known_data_gaps, notes. If the user asked for a comparison against observations, that goes in the framing; whether the data supports it is decided later, from the data.

Step 5 — Extract the run settings LLM

Forcingthe hard constraint, and it belongs to the model chosen in 2a. The runnable years are not in the prompt; they are in that report under constraints.forcing: years, years_partial, years_excluded, available, and bounded — which tells years: null apart from "no archive at all, take what you are handed". A period wholly outside the window is refused: clarification_needed, one question naming the runnable range, no substitute year. Partly outside → clamped, source user-clamped, conflict recorded.
Periodstated → resolved, source user. Not stated → ask_user is mandatory when present ("the archive covers X–Y, which year?"); in batch mode a single year inside the window, source default, conflict recorded. Decided on forcing alone — observation coverage is not the model's to weigh, because it has not seen it.
Column countonly a number the user stated goes in requested_n_columns. "A small study" is not a number. A count left in prose is a suggestion the planner is free to read past — it did, once, and designed 19 where 3 were asked for.
Initializationthe model's, not the LLM's. How a column starts is under constraints.initial_state in the report. run_settings.initialization is emitted only when the user stated a preference in their own words, as {mode, source: "user"}. Nothing is decided from the question.
Writesrun_settings {requested_period, requested_n_columns, resolved_period, [initialization], conflicts}; forcing_data, copied from the chosen model's constraints.forcing.

Between the halves — parse and route code

_parse() finds the outermost {…} in the model's final message; a failure returns intent: parse_error with the first 400 characters kept. _route() maps intent to route.action. If the action is not design, the package returns now — no fetch. If the brief is conceptual, any domain it resolved is removed, the removal is written into provenance as a decision, and the package returns — no fetch.

Gather 1 — gather_grid code

Callsterrain.get_watershed_boundary when the brief has a HUC and no boundary; terrain.sample_elevation_grid at GRID_N = 120, retried once on an empty reply.
Doesparses the WBD polygon into rings (Polygon and MultiPolygon, all parts), drops every point outside with a ray-casting test, and — when fewer than MIN_IN_BASIN = 55 land inside — asks again at a density scaled by the fill ratio, up to MAX_GRID_N = 480. A compact basin keeps ~50% of a bbox sample; an elongated coastal strip kept 18% and 21 points for 4,984 km².
Writesgrid {points (clipped), boundary, clipped_to_watershed, n_requested, n_returned, n_in_basin, elevation_min_m, elevation_max_m, relief_m}; and, into the brief, heterogeneity {relief_m, elevation_min_m, elevation_max_m, n_grid_points}. The model does not write heterogeneity; the planner stratifies on these numbers and the sampler sees the same points.
Rulea bad polygon must not empty the grid — but an empty fetch is not a bad polygon. If points came back and none survived the clip, the polygon is dropped and the raw sample kept; if no points came back, nothing is dropped. Conflating the two once cost two basins their boundary, every station tag, and all four pinned columns.

Gather 2 — gather_precipitation code

Callsdaymet.get_precipitation_points, one call for every grid point, budget 1,800 s.
Writesprecipitation {series["lat,lon"] → mm/day, calendar {year, yday} stored ONCE, elevation_m per point, n_days, years, covers, when}. The calendar is identical at every point, and 58 copies of it were 67% of the block. Daymet is a 365-day year: align by index, never by counting days off a real calendar.
Rulethe tool reports failures per point and carries no top-level error, so a pre-1980 period comes back as a successful call that fetched nothing. The tool's own ok is checked separately and folded back into provenance, so provenance cannot say ok: true beside an empty block.
Who reads ita model that takes forcing it is handed (PFLOTRAN's top boundary). A model that reads its own archive never opens it. Fetched anyway — see Appendix B.

Gather 3 — gather_observations code

Callsin one function, for the resolved period, one calendar year for every observable: usgs_water.get_streamflow, usgs_water.get_water_table, hydrodata.get_fan2013_wells, snotel.get_swe, ameriflux.get_et, hydrodata.download_conus2_wtd → wtd_conus2.tif.
Writessix blocks under observations: streamflow, water_table (daily recorder wells), water_table_static (Fan et al. long-term means, up to 500), swe (series kept on the 12 deepest-snowpack stations), et, water_table_modelled (the CONUS2 field, as a file). Every station is tagged in_basin against the grid's polygon — _inside, computed once, here. Absent means the check could not be made; absent is not false.
Thensummarise() writes brief.observations_summary: counts, station ids, coordinates, elevations, in-basin tags. Never a series. That is what the planner sees; the series go to the analyzer.
Rulea fetch that failed is written as ok: false with its error, and the analyzer turns that into a blocking caveat — "we could not look" is not "there is nothing there".

Gather 4 — gather_subsurface code

Callshydrodata.download_conus2_subsurface for the bbox → conus2_subsurface.npz + .json beside reception.json. Needs a run directory; without one it says so and fetches nothing.
What it isfive static ParFlow CONUS2 fields — porosity, vertical permeability, van Genuchten α and n, residual saturation — on ten layers to 392 m, SSURGO-derived above 2 m and hydrogeologic units below. It replaced a soil survey that stopped at 1.5 m and had 88–97% of a column extrapolated below it. The server keeps a basin cache keyed by grid bounds; the second study of a basin makes no request. 3.8 MB the first time.
Writessubsurface {ok, source, reused, n_requests, grid_bounds, arrays, meta, failed_fields} — a record of the fetch. The field itself is read later, at any point, by core.conus2_subsurface.sample.

The invariant. Both model servers today report the same top-level shape — model, pinning {model, pinnable, not_pinnable, vocabulary}, constraints {fixed, forcing, soil, initial_state} — and reception is written against that shape, not against either server's contents. A third server that reports the same keys is chosen, forced and constrained the same way without a line changing here.

Current guarantees

Enforced

  • Every gather.* call in reception_llm.py names a function that exists in data_gather, and binds against its signature. tests/test_call_sites_bind.py. Added 2026-08-18 after an edit deleted gather_precipitation and every site reception would have died after the LLM rounds.
  • The prompt states no initialization default and defers to constraints.initial_state; the config still warm-starts unless the user said cold. tests/test_soil_extraction.py::TestWarmStartIsTheDefault.
  • The prompt has no unfilled placeholder. Nothing is substituted at construction; load_prompt("reception_agentic") takes no arguments.
  • The three local tools exist and are exposed — list_servers, describe_server, describe_sweep — beside two terrain tools; nothing else reaches an MCP from the loop.
  • A conceptual brief fetches nothing, and its domain is dropped and recorded (_is_conceptual, _drop_domain).
  • The site path is unreachable without a resolved period — the observations, the rain and the subsurface sit under if isinstance(y0, int) and isinstance(y1, int).

Intentions, not guarantees

  • That the model reads two reports before choosing, cites them, and never names a model from memory — prompt instructions, checked by no test.
  • That the model refuses a period outside the chosen model's window rather than substituting a year — prompt instruction; a live-LLM test could pin it and does not.
  • That the model emits heterogeneity: null and no observations_available — the schema says so; if it writes them anyway, code overwrites the first four heterogeneity keys and nothing reads the rest.
  • That the gather is the same for every model — true by construction today, and stated in gather_subsurface's docstring as a decision; see Appendix B.
  • That a fresh reception with the current code produces a brief a downstream stage accepts — not yet exercised end to end for either model since the changes of 2026-08-17/18; see Appendix B.

Glossary

brief
the model-written half of the package: what is asked, which model, where, when, framed.
package
the whole return of process(): route, brief, and the four gathered blocks with provenance.
route
framework dispatch, kept out of the brief: design | clarify | analyze_existing | resume.
archetype
site (a place), conceptual (a controlled sweep, no place), coupling.
local tool
a tool the framework answers itself — list_servers, describe_server, describe_sweep — as opposed to an MCP tool a server answers.
report
a model server's own account of itself: describe_*_capabilities. Read whole, verbatim, one server per call.
pinning
in a report: what a column of that model may be compared against at a point, and why not, with basis.
constraints
in a report: what a plan may not vary — fixed, forcing, soil, initial_state — each with chosen_by and consequence.
can_run_a_study
the framework's flag on a server: is there a study wrapper for it. Not evidence about fit.
gather
the code half: gather_grid, gather_precipitation, gather_observations, gather_subsurface, in that order.
in_basin
reception's tag on every station, computed once against the grid's polygon; absent when it could not be computed, which is not false.
observations_summary
the compact, series-free view code writes into the brief for the planner.
provenance
one record per fetch — tool, args, time, ok, error — plus one for a fetch deliberately not made.
Appendix A

Design history

The fetcher left reception (2026-07-28)

Twelve tools in the loop meant the model spent 100–250 s of a 167–315 s reception choosing tools, then summarised results truncated to 12,000 characters — which is how it reported 25 gauges where 93 existed. Fetching became code, run once after the period is fixed. The model kept the judgements: what, where, when.

The comparison's vocabulary, and pinning only what a column produces (2026-08-07/08)

The sampler wrote water_table and the comparison read wtd; every well pin ever designed was silently refused. On the 13-basin chain run, 14 of 40 pinned columns went to stream gauges a 1-D column cannot reproduce. Stations became tagged in_basin against the polygon, once, in data_gather._inside; a pin outside the divide is refused downstream.

One slow request cost two basins their whole validation design (2026-08-09)

An empty DEM reply propagated as "no polygon", so no station could be tagged and the planner, told to pin only what it could confirm was inside, pinned nothing. The grid fetch is retried once, and an empty fetch is no longer treated as a bad polygon.

The model is chosen by reading, not by lookup (2026-08-17)

A rendered menu — a dozen lines per server, written at construction before the request was read, one line of it a verdict — was replaced by two local tools the model calls itself. It reads the reports whole. Measured live: a snow question picked ELM and quoted PFLOTRAN's report on why not; an unsaturated-flow question picked PFLOTRAN and said separately that it could not be driven yet.

The forcing window comes from the model's report (2026-08-17)

The prompt named NLDAS-2 and its years, from framework code that opened ELM's DATM directory. A PFLOTRAN study of 2024 was refused for a gap in ELM's forcing. The window is read from constraints.forcing of whichever model was named, and bounded: false says "no archive, no window".

The soil survey left; the subsurface arrived (2026-08-17/18)

gather_soil asked a geology server for SSURGO horizons at every grid point; a survey stops at ~1.5 m and everything below was extrapolated. gather_subsurface fetches ParFlow CONUS2's own parameterisation to 392 m, once per basin, cached server-side. The geology server is retired.

The last three model facts left the prompt (2026-08-18)

The sweep menu was rendered from a call hardcoded to elm and substituted into every prompt at construction — ELM's factors, before any model was chosen, under a heading saying they came from "the model server just now"; it is now describe_sweep, called on the chosen model, returning that server's JSON. Thirty lines of initialization guidance — one model's warm and cold starts from a particular restart file, applied to every request — became "read constraints.initial_state; emit nothing unless the user stated a preference". And six schema keys the model was asked to write and nothing read — a relief under a second spelling, band edges, a water-table prior with no producer since 08-07, a soil note, and two observation lists the model was told elsewhere not to write — were deleted.

The regression that made the binding test (2026-08-18)

The edit that retired gather_soil sliced the file from def gather_soil( to def gather_subsurface( and took gather_precipitation, defined between them. Reception went on calling it; the suite passed; the commit landed. Recovered verbatim from the session record, and test_call_sites_bind now walks every gather.* access against the module.

Appendix B

What is still open

The gather is unconditional on the model — a decision, recorded

An ELM study of a new basin downloads the CONUS2 subsurface and N years of Daymet that ELM never reads. gather_subsurface's docstring gives the reason: two runs of the same basin should carry the same provenance whatever was decided a moment earlier, and the cost is held by the server-side cache rather than by a condition. The alternative — each server's report naming what it takes from reception, and code gathering exactly that — is one list per server and one loop here. Not done; not clearly wrong either way.

Nothing has run end to end with the current code

The most recent ELM reception predates the model-choice rewrite, Daymet and the subsurface; the most recent PFLOTRAN one predates the forcing-window fix and carries forcing_data: NLDAS-2. Everything since was tested from those two files. One fresh reception per model — ~12 LLM rounds and every fetch, hydrodata included — is the missing check.

The coordinator, not reception
